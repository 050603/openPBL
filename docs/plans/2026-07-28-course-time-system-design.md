# 课程时间体系闭环设计

## 目标

把课程时间从“生成后展示的分钟数”升级为可执行的教学契约：

1. 备课建议必须显式读取课程主题、年级、难度、学习目标、学情、知识点层级和依赖关系。
2. 大模型负责教学判断和理由，确定性代码负责六阶段完整性、总时长守恒、最小边界与可追溯性。
3. AI 授知的每个页面同时拥有活动总预算、自然语速讲解预算、学生思考/操作预算和过渡预算；生成后再校验实际讲稿时长。
4. 授课时钟读取已确认时间表，跨刷新持久化，记录阶段实际用时、偏差和预计结束时间。
5. 自适应资源只能使用“自适应专用剩余预算”和“当前 AI 授知阶段真实剩余预算”中的较小值。

## 方案选择

不采用纯固定比例：它稳定但无法解释课程难度、知识依赖和学情如何改变时间。也不采用纯大模型输出：分钟总和、阶段缺失和极端分配难以保证。

采用混合闭环：

- 大模型输出六阶段建议、逐阶段理由、关键依据、假设和置信度。
- 归一化器把输出映射到六个标准阶段，过滤未知阶段，用受约束的整数分配保证分钟总和严格等于课程总时长。
- 模型不可用或输出无效时，使用现有上下文启发式作为显式降级来源，不伪装成 AI 建议。
- 教师确认后的分钟数仍是下游唯一时间契约。

## 数据流

```mermaid
flowchart LR
  A["课程事实、学情、知识图谱"] --> B["大模型时间分析"]
  B --> C["确定性归一化与边界校验"]
  C --> D["教师调整并确认"]
  D --> E["六阶段项目主线"]
  E --> F["页面/互动/测验预算"]
  F --> G["内容与讲稿生成后校验"]
  G --> H["课堂持久化阶段时钟"]
  H --> I["实际偏差与预计结束时间"]
  I --> J["自适应资源剩余预算"]
```

## 时间建议契约

`PblModuleTimingPlan` 增加可选审计信息：

- `recommendationSource`: `llm`、`deterministic-fallback` 或 `teacher`。
- `rationaleByStage`: 每阶段为什么需要这些时间。
- `evidence`: 模型实际使用的课程、学情和知识结构依据。
- `assumptions`: 缺失信息下做出的保守假设。
- `confidence`: `low`、`medium`、`high`。

大模型只建议阶段分钟，不直接生成项目主线和页面。解析器接受阶段 key 或常见别名，但最终只保留标准六阶段；分钟作为权重重新分配，并执行每阶段最少 1 分钟、实践阶段不被无意压缩等已有规则。

## 课堂运行时

`ClassroomTimingState` 保存绝对时间戳和已结算秒数，而不是每秒写数据库：

- 开始/重新授课时初始化六阶段预算。
- 运行中仅由浏览器每秒派生显示值，不产生写流量。
- 暂停、继续、阶段切换和时间调整时结算并持久化。
- 刷新或换设备后，用持久化时间戳恢复。
- 阶段切换会封存上一阶段实际用时，并激活下一阶段。
- 教师给当前阶段加减时间时，优先从未开始阶段按比例调剂；无法调剂的部分明确显示为预计延后。

课堂面板显示课程计划/实际、当前阶段剩余、偏差、预计结束时间以及六阶段状态，不再只显示一个无上下文的累计秒表。

## AI 授知和自适应

页面生成继续由模型决定语义页边界，但每页必须带结构化 `timingPlan`。生成器用自然语速估算全部 speech action，加上思考、操作和过渡时间做一次有界纠偏。最终场景保留目标预算，学生端实际播放继续写入学习事件，教师端可比较设计时长、实测语音和有效停留。

自适应插入的可用时间为：

`min(自适应计划剩余秒数, 当前 AI 授知阶段剩余秒数)`

如果课堂时钟缺失，则仅使用原自适应预算，兼容旧课程；如果 AI 授知已经超时，则停止新增扩展资源。

## 错误处理与验证

- 大模型未配置、超时或结构不完整：时间页仍可生成确定性建议，并清楚标记降级来源。
- 大模型分钟不守恒：确定性重分配，不让错误进入确认态。
- 旧课程无运行时钟：进入授课页时初始化，不破坏现有内容。
- 所有时间转换使用整数秒/分钟，测试固定 `now`，避免脆弱的真实时钟测试。
- 覆盖建议解析、总量守恒、暂停恢复、刷新恢复、阶段切换、调剂、超时、自适应预算夹取和 UI 关键状态。
