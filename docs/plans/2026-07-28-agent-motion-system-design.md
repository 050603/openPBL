# 智能体人物动作系统 C 方案设计

## 目标

在不改变“点击教室物件进入交互”的沉浸式设计前提下，建立一套适合课堂持续显示的智能体动作系统。动作需要更丰富，但不能喧宾夺主；动画必须以身体主干为稳定基准，不能因为手、围巾、文件或透明画布边界变化产生跳位。

## 动作目录

保留现有阅读、记录、规划、展示、讨论、思考、完成和错误等动作，并新增或重制以下 16 项：

1. `walking_horizontal`：重制横向交替步态，左右方向通过镜像实现。
2. `walking_up`：重制背向上行步态。
3. `walking_down`：新增正面下行步态。
4. `turn_arrive`：转身、收步和到站缓停。
5. `computer_typing_left`：头部、眼睛和上身朝角色自身左侧，连续输入。
6. `computer_browsing_left`：左向浏览及鼠标操作。
7. `computer_thinking_left`：保持左向屏幕，暂停输入并短暂思考。
8. `screen_pointing`：向电脑屏幕指示和讲解。
9. `raising_hand`：课堂举手。
10. `board_listening`：抬头看向教学区并倾听。
11. `comparing_materials`：在桌面资料和电脑间对照。
12. `looking_around`：短暂观察课堂和同伴。
13. `slacking`：低强度玩笔、整理围巾尾端或短暂走神，不出现手机游戏。
14. `stretching`：久坐后的短暂伸展。
15. `napping`：缓慢闭眼、点头和呼吸。
16. `waking_up`：收到任务或交互时自然惊醒并恢复专注。

## 动画架构

动作定义不再只保存一项全局 `animationSpeed`，而是包含视觉方向、帧率、主干锚点、循环方式和移动步幅。Pixi 画布继续以 60 FPS 渲染；行走素材按 10–12 FPS 播放，学习与交流动作按 7–9 FPS 播放，睡眠动作按 4–6 FPS 播放。增加帧数用于补足姿态变化，而不是简单加快旧帧。

行走速度由动作的“每循环位移”计算：`worldSpeed = pixelsPerCycle × authoredFps / frameCount`。容器保持线性位移，动画帧率和世界位移共同来自同一动作定义，因此不会因缓动或不同方向的固定速度产生脚底漂移。路线按照主方向选择横向、向上或向下动作；到达后播放一次 `turn_arrive`，再切换目标交互动作。

`Person` 播放器以 `bodyCore` 作为动作切换基准。每帧校正只允许修正整个角色画布的位置，不能用手、围巾尾端、文件或透明边界作为注册点。动作切换采用 120–180ms 的双精灵透明度过渡，并在过渡前后保持同一个视觉锚点。重复请求同一动作时不重建精灵，避免循环被无意义地重置。

## 空闲行为调度

动作按“任务、交互、环境动作、微休息”四级优先级调度。任务开始、发言、等待用户和课堂交互可以立即打断低优先级动作。`slacking`、`stretching`、`napping` 只允许在 `idle` 且角色位于座位时触发，并设置单角色冷却、全局并发上限和最近动作去重。

默认建议：

- 认真学习与轻微待机占座位空闲时间的 75% 以上。
- `looking_around`、`slacking`、`stretching` 使用低权重，冷却 45–90 秒。
- `napping` 需要连续空闲至少 75 秒，且同一时间最多一名智能体进入该动作。
- 新任务会先播放 `waking_up`，再进入电脑或学习动作。
- 电脑动作始终设置为左向，不继承角色上一次行走方向。

## 素材生成与质量门槛

每个动作使用同一标准人物视图、同一 canonical base 和独立 layout guide 单独生成。围巾母版色固定为 `#2E6BCB`，身体深蓝灰必须保持足够色差，后续换色只依据围巾掩码和连通区域，不按全图颜色距离直接替换。

所有动作必须通过以下门槛后才能接入：

- 192×208 RGBA 单帧，至少 8px 安全边距。
- 身体主干、头部和肩臂连接连续，无手臂脱节或围巾遮挡导致的结构跳变。
- 同一动作身体核心的帧间偏差不超过 2px，脚底或座位基线偏差不超过 4px。
- 首尾循环没有明显闪烁、反向跳跃或姿态断层。
- 小尺寸 Animated WebP/GIF 预览中动作语义清晰。
- 无背景色块、投影、速度线、文字、网格、透明孔洞和色边。
- 独立视觉检查明确通过；失败时重制完整动作批次，不拼接不同生成批次。

## 验证

自动化测试覆盖方向判定、步频与速度计算、动作优先级、冷却和重复播放去重。浏览器视觉验证覆盖横向/上行/下行路线、到站切换、电脑左向视线、空闲行为打断、多人同时显示和 30 秒以上连续循环。重点记录身体核心、脚底和座位锚点的逐帧位置，超过阈值即视为失败。
