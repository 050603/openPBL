# 首个教师账号注册设计

## 目标

为 OpenPBL 提供多教师账号创建入口，同时避免生产环境出现任何未登录访客都能注册教师的高风险权限漏洞。

## 方案

- `/teacher/register` 页面和 `/api/auth/register` 接口统一处理账号创建。
- 数据库中没有教师时，允许创建首个账号并自动登录。
- 已有教师时，只有持有有效教师会话的用户才能创建其他教师。
- 后续账号创建成功后不替换当前教师的登录身份。
- 保留 `pnpm admin:init-teacher` 作为服务器运维备用方式。

## 安全边界

- 服务端使用 Zod 验证用户名、显示名称、密码和确认密码。
- 密码长度为 12–256，使用现有异步 Argon2id 实现哈希。
- POST 请求执行同源校验，并按客户端 IP 限流。
- PostgreSQL 事务内获取注册专用 advisory lock，再检查教师数量和授权状态，避免并发绕过首个教师边界。
- 注册接口不接受角色、权限、教师 ID 或会话版本等客户端字段。
- 已有教师且请求未认证时返回 `401 TEACHER_AUTH_REQUIRED`。
- 用户名重复时返回 `409 TEACHER_USERNAME_TAKEN`。
- 生产环境缺少数据库或 JWT 配置时安全失败，不创建账号。

## 页面流程

1. 页面加载时读取注册状态。
2. 无教师时显示首个账号表单；已有教师且已登录时显示新增教师表单。
3. 首个账号创建成功后自动登录并跳转 `/teacher`。
4. 后续账号创建成功后显示结果并保留当前登录身份。
5. 已有教师但未认证、或服务不可用时不渲染可提交表单。
6. 教师个人菜单提供新增教师入口。

- 单元测试覆盖输入校验、注册路由模式和旧令牌边界。
- Route Handler 测试覆盖已初始化拒绝、成功创建及 Cookie 返回。
- 执行 TypeScript、零警告 ESLint、全量 Vitest 和生产构建。
