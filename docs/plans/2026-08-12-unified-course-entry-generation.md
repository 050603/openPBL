# 统一课程入口学习包生成设计

## 问题

旧链路分别生成并审校先修知识图谱和个性化学习方案。一次成功至少需要四次模型调用，重试时最多达到十二次；任一环节失败都会保留数据库里的旧空方案。手动生成接口还只把结果返回浏览器，再依赖页面状态完成第二次保存。因此，用户会看到旧方案被标记为“方案不完整”，却得不到新前测。

## 决策

将旧的分段生成器替换为单一的“课程入口学习包”生成器：

1. 生成代理一次返回学段判断、课程深度、知识阶梯、真实先修能力、每项先修的一道前测题和一份补学页脚本，以及少量课后拓展。
2. 独立审校代理不只给通过/拒绝结论，而是必须返回一份完整的最终修订稿。即使首稿结构不完整，审校代理也负责补全。
3. 程序从最终修订稿一次性编译知识图谱与个性化学习方案。知识点 ID、题目 ID、补学资源 ID 和关系由程序生成，模型不再维护跨对象引用。
4. 编译后执行确定性质量门：每课 1–5 项真实先修（推荐 2–4）、一项先修恰好一题一资源、每项必须指向本课目标、前测时长受限、补学在主课前、拓展只在课后达标测之后。
5. 手动生成接口在服务器端原子保存知识图谱和个性化方案，再把已保存结果返回页面。失败不会把空方案当成成功，也不依赖浏览器完成关键保存。

## K12 语义

“知识启蒙”描述学习者仍处在系统学习阶段，不构成零先修豁免。分析顺序固定为“学段 → 本课在学科知识阶梯中的深度 → 本课目标所需入口能力”。年级缺失时按“K12 学段待确认”保守分析。计算机视觉、自然语言处理等主题在 K12 中属于较深入主题，应回溯人工智能、数据与数据集、机器学习流程、监督学习、特征等真实台阶，但最终内容必须依据当前课程目标生成，不能套用固定题库。

## 失败策略

正常路径为生成一次、独立审校修订一次。最终稿若仍未通过确定性质量门，允许一次定向发布修订；仍失败则返回明确生成错误并保留原数据。界面不得把历史空方案描述为新的成功结果。
