# ADR-0006：快速生成编排标准课程设计能力

## 状态

已接受

## 背景

快速生成最初通过一次 `fullCourse` 调用取得整门课程，再把结果拆成若干进度记录。这条路径没有真正执行分步设计中的课程定位、项目成果确认、评价责任校验、PBL 六阶段时间确认和 OpenMAIC 主课脚本约束，导致两种模式的数据质量和资源覆盖不一致。

快速模式的目标不是建立第二套简化生成器，而是让 AI 代替教师依次调用既有领域能力、审核结果，并在合格后进入下一阶段。两种模式必须写入相同的 `Course` / `CourseContent` 契约。

后台任务会运行数分钟，其间页面操作、会话事件或其他工作器可能递增 `Course.version`。因此后台任务不能把启动时读取的完整课程快照重新写回数据库。

## 决策

- 快速生成依次执行课程定位、目标与知识图谱、项目成果、成功标准、六阶段架构、主课脚本、个性化路径和综合质量复核。
- 各阶段复用分步模式的领域能力：课程定位使用项目骨架能力，知识图谱、评价、时间和架构使用共享 LLM action，主课脚本使用共享 OpenMAIC outline generator 和 PBL contract。
- 各阶段先调用与分步模式相同的生成能力，再执行确定性结构检查和 AI 审校。AI 审校发现目标不一致、范围过大、角色缺失等内容质量问题时，由快速设计代理携带完整阶段快照和审校意见进行定向修订或重新生成，随后再次审校。
- 内容质量意见属于代理的工作，不能直接把快速任务置为失败或要求教师返回输入页。经过多轮修订后，只要必要结构完整，代理采用当前最佳版本继续，并把剩余建议写入追踪记录；只有必填结构仍缺失、模型调用不可恢复、持久化失败等系统性问题才终止任务。
- 课程定位阶段必须整体协调课程说明、目标、驱动问题和固定课时：驱动问题中的核心概念与成果必须由目标覆盖；课时不足时优先缩减案例、目标或成果范围，不得擅自增加教师指定课时。
- 主课脚本生成后，在快速页面内部提供独立审阅弹窗。教师打开即暂停，保存后使用最新 scene outlines 继续；未打开则在等待窗口结束后自动继续。
- 工作器写课程时只把本阶段的“课程设计字段”合并到数据库最新快照，并保留最新 `version`、学生、课堂运行和会话数据。禁止使用捕获的旧 `Course` 替换完整聚合。
- 快速生成追踪记录可以携带 `CourseDesignGenerationArtifact`。这些产物来自已经生成并保存的真实课程数据，供全屏进度画布展示课程信息、知识图谱、成果、评价、时间线、课堂页面、分支和审校报告。
- 快速生成画布按产物产生顺序单向推进，不循环旧卡片；重新进入页面时恢复到最新产物。
- 课程设计任务完成后不再跳转普通生成页。画布继续订阅同一门课程的 `CourseGenerationJob`，用真实大纲标题展示页面制作、媒体资源和自动保存状态。
- 最终课堂任务必须先通过 `linkClassroomToCourse` 持久化学生课堂与教师资源，再标记任务完成；发布不是保存前提。
- 本机环境通过显式动作领取已经持久化的排队任务，生产环境仍由长驻工作器领取，两种环境共用同一生成器和同一保存路径。
- 丰富互动由共享 interactive-mode policy 实施；学生 PPT 单页上限为 6 分钟，教师资源时长仍表示学生完成活动所需时间，不做机械拆页。

## 结果

### 正向

- 两种模式使用相同的数据结构、PBL 阶段约束、教师资源覆盖和互动策略。
- 长时间后台生成不会用旧版本覆盖教师或课堂中的新数据，也不会因固定旧版本反复冲突。
- 教师看到的是本次课程的真实中间产物，而不是固定动画文案；进度可理解、可追溯。
- 教师可以在快速流程内审阅关键脚本，又能返回原生成画布继续任务。
- 教师不再需要处理普通的阶段审校意见；代理负责修订并继续，教师只在主课页面大纲检查点介入。

### 代价

- 快速生成会产生更多模型调用，完成时间和 Provider 成本高于单次 `fullCourse`。
- 后台工作器必须处理长任务、阶段重试、版本并发、大纲暂停和任务恢复。
- 多轮生成、审校和定向修订会增加模型调用次数，但这是快速模式替代教师逐阶段确认所需的成本。
- 进度接口和追踪数据会增加少量 JSON 体积，因此产物卡片必须限制条目数量。

## 否决方案

### 继续使用 `fullCourse`，生成后补字段

否决：无法保证真正执行课程定位、项目成果、评价分工、时间确认和主课脚本契约。

### 复制分步页面的 React 点击逻辑

否决：UI 事件不是可恢复的后台领域能力，教师离开页面后也无法可靠运行。

### 快速模式使用独立数据模型

否决：课程不可追溯，教师后续进入高级分步设计时会缺少阶段数据。

### 在版本冲突时重复保存旧完整快照

否决：即使最终写入成功，也可能覆盖其他并发操作已经保存的数据。正确做法是基于每次最新读取进行字段级合并。
