# ADR-0007：质量不降级的课程生成并发与检查点

## 状态

已接受

## 背景

课程快速生成的最近一次完整任务中，最终课堂生成明显慢于课程方案设计。主课页面已经采用有限并发，但个性化分支仍逐条串行；主课页面只在整批生成结束后持久化；图片、语音和分支资源也未充分重叠。直接减少模型调用、缩短提示词、关闭审校或把多阶段合并为一次调用都可能降低课程质量，不符合本项目要求。

## 决策

- 所有核心生成职责保持不变：页面内容、授课动作、时长修正、阶段审校和全课程复核不减少。
- 不同主课页面可以并发，但单页内部继续执行“内容 → 动作/讲稿 → 必要的时长修正 → 页面检查点”。
- 个性化分支使用固定并发度 3；每条分支仍调用相同生成器、相同模型配置和相同质量约束。
- 所有后台课程生成模型调用共享一个进程级 FIFO 并发闸门，默认上限为 4，可通过环境变量在 1–5 之间调整。该闸门只限制课程生成上下文，不阻塞课堂中的交互式 AI 请求。
- 主课页面完成后立即写入数据库检查点。恢复时只有课程大纲指纹一致的页面才可复用，并且复用页面仍参加最终全课程质量复核。
- 个性化分支完成后立即字段级合并到最新课程聚合，不等待全部分支结束；失败分支也单独记录，不覆盖其他成功结果。
- 主课持久化并关联课程后，个性化分支与图片/TTS 资源并行执行；任务完成仍以两条流水线都收敛为前提。
- 课程方案设计只恢复已经保存、带完成追踪记录且重新通过确定性结构检查的阶段。存在上游依赖的生成阶段不做推测性并发，也不跳过 AI 审校。

## 质量保证

- 不改变模型、思考配置、输出上限、提示词职责或重试策略。
- 页面检查点位于单页时长修正之后、全课程复核之前。
- 恢复页面重新绑定当前 stage，并再次执行课程完整性、知识边界和测验规范化检查。
- 并发失败只重试当前页面或分支，不触发质量降级回退。
- 429 或服务波动由全局闸门和现有重试策略处理，不通过减少内容规避。

## 失败模式与缓解

| 失败模式 | 缓解 |
|---|---|
| 多个生成任务同时打满模型配额 | 课程生成上下文共享全局并发闸门 |
| 进程在第 N 页后退出 | 按大纲指纹恢复已完成页面 |
| 分支并发写入互相覆盖 | 每条分支基于数据库最新课程做字段级合并 |
| 旧页面错误复用于新大纲 | 大纲 SHA-256 指纹不一致时强制重生 |
| 并发进度事件互相覆盖 | 所有任务进度写入经过同一串行队列 |
| 单页检查点尚未经过课程级复核 | 恢复后仍执行完整课程复核和修复 |

## 代价

- 新增页面检查点表和一份已准备大纲快照。
- 后台任务的调度、进度聚合和恢复路径更复杂。
- 进程级闸门不能跨多个容器协调；多实例共享同一供应商密钥时仍需后续升级为 Redis 租约闸门。

## 否决方案

### 把单页三次模型工作合并成一次调用

否决：上下文、输出结构和失败半径同时增大，无法证明质量不降级。

### 直接把所有并发提高到 10

否决：容易触发 429 和重试风暴，实际更慢且稳定性下降。

### 只保存整门课程

否决：进程中断后必须重新生成已经合格的页面。
