# 系统提示词质量审计

审计日期：2026-08-09

## 审计范围

本次审计覆盖了系统内可检索到的运行时大模型调用、PBL 课程生成提示词、自适应资源提示词、教师课堂支持、学生伴学、主观题评分、智能体画像、课程封面，以及 OpenMAIC 的 40 个 Markdown 提示词模板。重点检查：任务定义、输入边界、语言一致性、证据使用、学段适配、结构化输出、教学责任边界和结果自检。

## 发现的根因

此前出现“难度 standard”“priorKnowledge 为空”“foundation → core”“proposal 阶段”等文本，并非模型随机失常，而是三类系统性问题叠加：

1. TypeScript 内联提示词直接拼接了阶段代码、难度枚举和原始 JSON，模型随后把这些内部字段当成可展示的课程语言复述。
2. 不同生成入口各自编写语言和证据规则，部分入口只有“返回 JSON”，缺少“自然语言字段必须中文”“空值只表示未知”“内部代码不得进入展示文本”等约束。
3. 生成结果主要校验 JSON 结构，过去缺少统一的展示文本本地化层；即使模型偶发泄漏内部术语，也可能直接被保存和显示。

## 统一质量契约

所有核心提示词现在统一遵守以下规则：

- 语言：中文业务场景的所有展示文本使用自然、准确的简体中文；英文只用于必要的标准专名、代码、公式、JSON 键和指定枚举。
- 证据：只依据明确提供的课程、学生和过程证据；空值、缺失字段和无记录一律解释为“未知/未填写”，不能推断为“不存在”“没有能力”或“已完成”。
- 任务：只完成当前字段和当前生成目标，不以通用套话、无关扩展或虚构细节填充。
- 受众：难度、术语、示例和任务量匹配学段；AI 不替代学生完成核心成果，也不替代教师作最终判断。
- 输出：内部字段名、阶段代码、枚举值、证据 ID 和生成过程只允许出现在规定的结构字段中，不进入标题、依据、说明、讲稿、反馈等展示文本。
- 自检：返回前静默检查事实依据、内部一致性、术语准确性、学段适切性、字段完整性和可执行性，只返回修正后的结果。

## 已修复的生成链路

| 链路 | 主要修复 |
| --- | --- |
| 课程定位与备课建议 | 使用中文学生画像和教学边界；不再把 `high-school`、支架代码和英文规则传给中文候选生成 |
| PBL 大纲、知识图谱、时间安排、授课大纲、评价 | 接入统一 JSON 教师契约；知识图谱增加节点一致性、连通性、关系方向与教师必选知识点校验 |
| 教师课堂诊断与反思提示 | 阶段、评价来源、学习进度和采纳状态改为中文语义；停止直接拼接学习事件元数据和阶段代码 |
| 学生伴学与普通聊天 | 服务端追加统一学生对话契约；明确只基于已有证据、一次解决一个问题、不暴露内部字段和推理过程 |
| 自适应资源与微课判断 | 限定自然语言字段为中文；枚举和 ID 只能出现在 schema 字段；阶段信息改用中文名称 |
| 主观题评分 | 明确评分证据边界、空答案处理、反馈结构和语言规则，不猜测学生未写出的推理 |
| OpenMAIC 课程/互动/通用大纲 | 强化语言推断、内部元数据隔离、缺失信息语义和返回前自检 |
| 智能体画像 | 角色代码、头像路径、语音 ID 和颜色只作内部元数据，不得进入人物名称和可见描述 |

## 保留英文的合理场景

以下英文不属于错误，不能机械翻译：

- JSON 键、固定枚举、数据库/路由 ID 和工具调用参数；
- Python、Docker、AI 等标准产品名或技术专名；
- 代码生成、网页生成和模型内部编排指令；
- 非中文课程明确要求使用的教学语言；
- 无可见文字的课程封面图像生成指令。

这些场景仍须遵守一条边界：英文内部结构不得被复制到中文课程的用户可见内容中。

## 防回归措施

- `src/lib/prompt-quality/policy.ts` 作为统一规则源，核心内联提示词不得自行复制一套弱化规则。
- `src/lib/llm/generated-language.ts` 对课程生成结果中的历史泄漏词进行二次本地化，结构枚举保持不变。
- `src/lib/prompt-quality/adoption.test.ts` 检查核心链路是否持续接入统一契约。
- 知识图谱和课程时间安排继续使用确定性质量校验；不合格结果报错重试，不能静默存入课程。
- 新增提示词时，必须先确定受众、语言、证据来源、输出 schema、责任边界和静默自检，再接入运行时调用。
